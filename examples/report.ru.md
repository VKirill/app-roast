### Хранение

<a id="f-001"></a>
#### F-001 — Добавление не сохраняет задачу

**S-001 · CONFIRMED-RUNTIME · P1.** Основной сценарий: пользователь получает успешный ответ на создание, но новая задача недоступна следующему процессу.

1. Создать одноразовую копию seed.
2. Выполнить `add "New durable task"`: ответ `Saved`, новая задача ID 4, exit code 0.
3. Другим процессом выполнить `list --all`, затем `show 4`; прочитать JSON.

**Ожидание:** новая задача есть в файле и читается. **Факт:** список и файл содержат только IDs 1,2,3; show возвращает ошибку. Повторено на двух независимых базах. [Доказательства: add-1, add-2](evidence/runtime-checks.json).

**Причина:** [ветка add](../evals/fixtures/pocket_tasks.py#L25) изменяет список в памяти и печатает успех, но не пишет файл. Общего сохранения после веток нет. Контрпример проверен: [archive](../evals/fixtures/pocket_tasks.py#L32) вызывает запись и сохраняет состояние. Не заявляем потерю ранее существовавших задач или поломку всех записей на диск.

**Исправление:** сохранять изменения до сообщения об успехе, не выдавать ошибку записи за Saved. **Приёмка:** add → новый процесс show/list видит новую запись; отказ записи возвращает ошибку и не сообщает об успешном сохранении. Исправление не выполнялось.

### Представления данных

<a id="f-002"></a>
#### F-002 — Счётчик активных включает архив

**S-002 · CONFIRMED-RUNTIME · P2.** На неизменённой базе `list` возвращает две активные задачи, `stats` — `active=3,total=3`.

**Воспроизведение:** свежий seed → list → stats. Ожидание active=2, факт active=3. Повторено на двух базах. [Доказательства: counts-1, counts-2](evidence/runtime-checks.json).

**Причина:** [stats](../evals/fixtures/pocket_tasks.py#L40) вычисляет оба поля через `len(tasks)`. Контракт явно определяет active как активные; это не допустимый глобальный счётчик. total=3 корректен.

**Последствие:** сводка завышает объём текущей работы при наличии архивных задач. **Исправление:** считать active по тому же предикату, что list. **Приёмка:** active равно длине list до и после архивирования, total равно длине list --all.

<a id="f-003"></a>
#### F-003 — Фильтр экспорта меняет подпись, но не состав

**S-003 · CONFIRMED-RUNTIME · P2.** `export --status active` выгружает IDs 1,2,3, хотя list отдаёт только 1,3.

**Воспроизведение:** свежий seed → list → export active → export all. Active должен совпасть с list; фактически совпадает с all. Повторено дважды. [Доказательства: export-1, export-2](evidence/runtime-checks.json).

**Причина:** [export](../evals/fixtures/pocket_tasks.py#L42) возвращает весь tasks; аргумент меняет только поле status. Внешнего фильтрующего адаптера в этом CLI нет.

**Последствие:** выгрузка текущих дел включает архивные записи. Утечка чужих данных или фактическая обработка внешним сервисом не наблюдались. **Исправление:** применять отбор для active. **Приёмка:** IDs export active равны list, IDs export all равны list --all; повторить после архивирования.

### Ошибки CLI

<a id="f-004"></a>
#### F-004 — Отсутствующая задача возвращает код успеха

**S-004 · CONFIRMED-RUNTIME · P2.** `show 9999` возвращает `{"error":"Task not found"}`, но завершает процесс с кодом 0.

**Воспроизведение:** свежий seed → show отсутствующего ID → проверить код завершения. Ожидание — ненулевой код; факт — 0. Повторено дважды. show существующего ID работает; archive отсутствующего ID возвращает 1. [Доказательства: missing-1, missing-2](evidence/runtime-checks.json).

**Причина:** [show](../evals/fixtures/pocket_tasks.py#L44) печатает ошибку, затем main нормально возвращается. **Последствие:** автоматизация, проверяющая exit status, получает ложный успех. Ошибку в JSON приложение не скрывает.

**Исправление:** явно возвращать ненулевой статус для отсутствующей задачи. **Приёмка:** существующий ID → объект и 0; отсутствующий → ошибка и ненулевой код.

### Отклонённое подозрение

**R-001 — Нет аутентификации. REJECTED.** Продукт по контракту — локальный однопользовательский CLI. Роли и удалённый доступ не обещаны. Отсутствие логина не является несостыковкой этого продукта. Исправление не требуется.

## 5. Прожарка

[F-001](#f-001): Pocket Tasks говорит «Сохранено», а следующий процесс уже не помнит твою задачу. Охуенный ежедневник: стирает запись быстрее, чем ты успеваешь передумать её выполнять.

[F-002](#f-002): Архивные задачи исчезли из списка, но остались в активном счётчике. У этой бухгалтерии, блядь, даже уволенные продолжают закрывать план.

[F-003](#f-003): Фильтр active меняет только подпись на выгрузке. Сука, это не фильтрация, это переименование пакета с тем же самым содержимым.

[F-004](#f-004): Задачу не нашли, код успеха выдали. «Нихуя не получилось, операция выполнена» — готовый девиз этого exit status.

## 7. Покрытие и ограничения

Проверены контрактные команды, два режима экспорта, сохранение архива и отсутствие новой записи после завершения add. Каждый вызов выполнен отдельным процессом. Дефекты повторены на свежих копиях seed.

Не проверены повреждённые JSON-файлы, конкурентные записи, сбои диска, большие объёмы и другие ОС. Сетевая безопасность и браузерный интерфейс неприменимы. Исходники не изменены; временные базы удалены после записи доказательств. Полный аудит произвольного production-приложения этим примером не подтверждается.
